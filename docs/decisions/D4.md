## Bottom line

- **The Biome choice needs no new design.** W0 chooses each region's
  Biome type freely from the selector fields (E, ruggedness, moisture)
  and pins, on today's region graph. Neighbours may land on the same
  type. There is no change to the graph, W3's warp or W4's region cache,
  and `RegionId` and `region_seed` stay as D3 set them.
- **Same-type neighbours blend like any border.** Each region's Biome
  instance has its own seed, so two "pine forest" regions side by side
  have different cover, and the Ecotope border protocol blends it. Their
  Scatters have equal priorities on both sides, so who wins at each spot
  along the border falls to D3's tie-break by address prefix (region,
  Ecotope salt, Scatter salt). That border is a bit random; the user
  accepts that (2026-11-24: "who cares").
- **What is still open: region size and shape** (world_plan.md open
  question 2): how large regions are, and whether they are even or a
  multi-scale mix. See "Region size".
- **It waits on two inputs:** the quiet-machine rerun of the G3 step 2
  cold benchmarks, and W0's image example.
- **D4 no longer blocks W0's Biome choice.** W0 needs only a region
  size, and can start on today's 4 km default
  (`RegionGraphOptions::default`).

## The question

How large should regions be, and should they be even or a mix of sizes?
ROADMAP's D4 row moved world_plan.md's open question 2 (region size and
shape) here. The rest of the first draft's question (keeping neighbours
on different Biomes) was a misreading of D3 and is superseded.

Placement seeds are chained World → region's Biome → Ecotope → Scatter
(D3, question 1), so every region border is a seam in every Scatter,
which the Ecotope border protocol blends, whether the two Biomes are of
the same type or not. Region size therefore also sets how often a large
area of one Biome type is crossed by such blended seams.

## Constraints on region size

1. **Stable, local `RegionId`.** A region's id and outline must be pure
   functions of the World's options and seed, computable from a bounded
   neighbourhood, and the same whatever order regions are asked for, on
   any thread. Seeds (`region_seed(W, role, region)`) and every
   `CopyAddress` carry the `RegionId` (D3).
2. **Any build order.** Nothing may depend on which regions were built
   first (world_plan.md, "Why a field").
3. **Valid terrain regions.** A `Region`'s `Boundary::Polygon` is a
   simple polygon with no holes. Edges must be at least `MIN_EDGE`
   (390 m) so a crossing fits. A region must be several times (margin +
   taper) wide.
4. **W3's warped borders.** `warp_side` wiggles each straight side
   between two corners, faded to zero over half a wavelength at each
   corner. Its default amplitude and wavelength are set for a few-km
   region.
5. **W4's region cache** builds each region once under a per-key lock,
   in an LRU cache keyed on `RegionId`, so region size sets the plan time
   and memory per entry.

## Region size

**Not fixed here.** It waits on the terrain lane's G3 step 2 cold
benchmarks, running in parallel. features_plan_review.md says that if
Conflict 4 goes to region-level planning, "region size sets how long a
region's plan takes, so D4 should see step 2's cold benchmarks before it
fixes region sizes." It went that way: planning stays per region, with
macro cells only if step 2 calls for them.

What region size affects:

- **Plan time per region.** The figures already measured are these.
  About 0.3 s per 10 km region (556 ms for two, world_plan.md). Road
  routing takes about 25 ms on plains and up to about 1 s in mountains,
  plus 80 to 170 ms for road-grid heights (ARCHITECTURE, "Plan").
  Planning work grows with area, and road routing likely grows faster.
- **The plan-ahead ring.** Regions are planned one region beyond the view
  distance, so larger regions mean more area planned before it is seen,
  and more plan memory in the W4 cache.
- **Biome patch size.** Neighbours may share a Biome type, so an area of
  one type can span many regions and is not capped by region size.
  Region size sets the smallest Biome patch (one region), and how often
  a large area of one type is crossed by blended seams between instances
  (see the next point). It no longer forces large regions to get large
  Biome areas, so G3's plan time and Biome patch size are no longer tied
  together.
- **How often same-type neighbours meet.** E's layers have wavelengths
  of 40 km (uplands) and 150 km (continents), against 4 km regions
  today. So neighbouring regions sample nearly the same field values and
  will usually pick the same Biome type. Each such border is an
  Ecotope blend between two instances, decided spot by spot by the
  address-prefix tie-break. Smaller regions mean more of these borders.
  Whether they show is for W0's image example, and later the first
  Ecotopes, to judge.
- **Border share.** Border length per km² falls as 1 / size. Near borders,
  heights cost more (warped borders are about 2.7 times straight ones),
  and the Ecotope blend zones take a larger share of the land.
- **Limits already in code.** `size` ≥ 5 × `min_edge` (1950 m at the
  default), `size` ≤ `MAX_SIZE` (50 km, for exact i128 arithmetic), and
  "several times (margin + taper)" for each Terrain. The warp default
  (100 m / 800 m) is set for a few-km region.
- **Shape and variety** (world_plan.md open question 2: even regions, or a
  multi-scale mix?). Today's graph gives even regions: warped hexagonal
  cells, varied only by jitter. A true multi-scale lattice (large
  regions with occasional small ones) is one way to get variety. It was
  not worked out here.

- **Decide region size and shape after two inputs:** the quiet-machine

  graph's construction.

  open question 2). Even regions at one size, and which size? Or a
  multi-scale mix, which would need its own design?

**Build W0 on A,** with the ranked, priority-ordered choice and

- It meets the id and geometry constraints with no code change, and it
  is the only option that costs nothing in G5's graph, warp or W4 cache.
  It does not yet meet two others: its choice chain has no hard bound
  (constraint 1, open question 5), and three Biomes can't satisfy the

  alternating at cell scale look wrong, move to B1, or to B2 if Biome

  the graph independent of the World's rules.
- Keep C for bounded and designer-polygon worlds, where a finite flood
  fill (or the designer's outlines) is fine.

**What would change this recommendation:**

- If the user wants Biome areas to follow the fields at their full size
  (open question 4), A is the wrong start: go to B2 directly.
- If G3 step 2 shows that cold plans of regions several times today's
  size are too slow, B's larger regions become expensive, and A stays.
- If measuring W0 shows long choice chains or frequent fallbacks, a hard
  bound (periodic priority classes) or more candidates per family is
  needed first.
- If the user exempts cover-less Biomes (open question 3), ocean no
  longer forces alternation, and A looks much better.

**What W0 must have, in any case:** more candidate Biomes per region
than it has neighbours, or a defined failure (open question 2), or the
exemption in open question 3. Three empty Biomes can't satisfy the rule
everywhere (constraint 9).

## Open questions for the user

1. **What does "share a Biome" mean?** The same Biome preset? Or a Biome
   with the same Ecotopes (two presets that differ only in their Terrain
   would then also count as "the same")? Or the same Terrain preset?
2. **Must rule sets supply fallback Biomes?** Under A and B, a region
   whose best Biome is taken by a neighbour falls back to its next
   candidate. Should each rule name a family of siblings (for example
   "alpine forest", "alpine meadow", "scree")? Or may the rule fall back
   to any Biome, ranked by field distance? And what happens when every
   candidate is taken: a validation error for the rule set (requiring
   enough candidates), or something else?
3. **Are Biomes with no cover exempt?** The seam the rule prevents is a
   *cover* seam (chained Scatter seeds). Two neighbouring regions on the
   same empty Biome (ocean, bare plains) have the same Terrain preset on
   the same World noise and no Scatters, so there is no cover seam. The
   ordinary terrain seam between two regions stays (per-region plans,
   margins and ports), as it does at every region border.
   Exempting them would let oceans and bare land stay one Biome. W0 is
   all empty Biomes, so under this exemption it would need no rule at
   all. This narrows D3's rule; it does not reverse it.
4. **What should large uniform areas look like?** A 100 km ocean, or a
   continent-wide plain: one Biome everywhere (only bounded worlds, or the
   exemption in question 3), alternating siblings at a fixed scale (A,
   B1), or field-shaped areas cut along block lines (B2)?
5. **Is a hard bound on the choice chain required?** Or is an expected
   length of a few steps, measured on W0, enough?
6. **Holes** (B and C only): absorb an enclosed patch into the region
   around it, or split the surrounding region with a cut?
7. **Region size and shape:** see "Region size". To be decided after G3
   step 2's cold benchmarks, and after W0's image example if A is chosen.
